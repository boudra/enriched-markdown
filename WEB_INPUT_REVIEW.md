## 0. Verdict in one paragraph

The port is structurally faithful to iOS/Android and the model layer (stores, adjust-for-edit, projection) is sound for composer-sized documents. It is not ready for a large-document or mobile-heavy audience yet. Three clusters dominate: (1) IME/composition handling can desync screen and model, in one case making a whole line vanish from the screen; (2) markdown round-tripping corrupts ordinary text on every save/load, both at import (remend) and at serialize (no escaping, wrong delimiter nesting); (3) per-keystroke cost is O(document), and the single biggest cost at scale is the scripted caret restore after each keystroke, which jsdom cannot see. Several things web does better than native and should be ported back; the native input stacks have no unit tests at all.

## 1. PRIORITIES

### P1-A — "Cursor magic": caret, selection and composition

Why first: these are the data-loss and feel-wrong paths, and the caret restore is the biggest per-keystroke cost at scale.

Measured facts [B]:

| 69K chars · 1243 lines · 2072 ranges, typing mid-document | avg ms | max ms |
|---|---|---|
| whole keystroke (`applyEdit`) with `onChangeMarkdown` | 6.0 | 22.7 |
| whole keystroke without `onChangeMarkdown` | 5.0 | 22.1 |
| `Selection.setBaseAndExtent` (caret restore inside `writeSelectionToDom`) | 3.4 | 4.0 |
| of which forced style+layout (probe: `offsetHeight` right before the write) | 0.8 | 1.3 |
| of which selection-specific work after layout is already clean | 2.5 | 3.6 |

- Caret restore scales with document size: 0.42 ms @ 49 lines, 0.70 ms @ 249, 3.4 ms @ 1243. Whole keystroke: 0.84 / 1.2 / 5.0 ms.
- Why it is always needed: `patchRun` assigns `textNode.nodeValue`, which collapses the live caret to offset 0 in Chromium (probe: caret 6 → 0). `replaceData(k,0,'Q')` at caret k leaves the caret at k (before the insert, per spec); `deleteData` before the caret moves it correctly; `insertData` same as replaceData. So a minimal `replaceData` diff fixes deletions and preserves spellcheck markers, but insertions still need one selection write.
- No other forced layout exists on the keystroke path; `caretRect()`/`measure*` are on demand only.

Work items (done 2026-10-15, uncommitted on `feat/web-input`, except the "Decide" item; regressions in `W/editing/__tests__/InputHostCaret.test.ts`; IME/scroll/caret-rect/backward-selection re-verified in Chromium via CDP `Input.imeSetComposition`; per-keystroke cost unchanged at 1243 lines, ~2.1 ms, still dominated by the caret restore):

Constrain the diff to the DOM caret (prefix ≤ caret, suffix ≤ newLen − caret, ProseMirror `findDiff` style), take `selection` from the DOM caret, cross-check `CompositionEvent.data`. Gboard composes every word, so this is the mainstream Android path.
- [x] **Composition guard for commands, `setSelection`, imports and `render`.** `toggleBold()` mid-composition moved the DOM caret 6 → 3 under the IME; a caret toggle during composition bolds the word being typed; `setValue` mid-composition rewrites nodes under the IME [J], and if the IME writes again `recoverComposition` diffs its leftovers against the *new* model (in jsdom nothing was left over, so this half is [R]). Make `writeSelectionToDom` a no-op while composing; flush or defer commands/imports to `compositionend` (`InputHost.ts:233-323, 763-813`).

Clear on `compositionstart`, recompute on `compositionend` (`InputHost.ts:765-768`, `W/render/inputStyles.ts:62-71`).
- [x] **Composed text is excluded from `value`, `onChangeText`, `getMarkdown`** until commit; on Chrome Android text stays composed until a space, so a Send button that keeps focus drops the last word [J]. Android native processes composing changes (`A/EnrichedMarkdownTextInputView.kt:387-418`). Model-only update on `input` with `isComposing` (no render), or flush in `value`/`getMarkdown`.
- [x] **Scroll the caret into view after edits.** Programmatic `setBaseAndExtent` does not scroll: typing/Enter at the bottom of a 120px `overflow:auto` editor leaves `scrollTop` 0 with the caret 1900px below the box [B]. Scroll the caret rect into view after `applyEdit` (not after selection echoes), as ProseMirror/Slate do (`InputHost.ts:807`).
- [x] **Use `replaceData` with a minimal prefix/suffix diff in `patchRun`** instead of `nodeValue =` (`DomRenderer.ts:301-305`). Preserves Blink spellcheck markers outside the edit; caret stays correct for deletions; probe numbers above.

### P1-B — Undo/redo stack

State today [B]: Ctrl+Z, Ctrl+Shift+Z/Ctrl+Y, Edit-menu undo and iOS shake-to-undo do nothing. `historyUndo`/`historyRedo` arrive as `beforeinput` and are cancelled by the default-deny branch (`InputHost.ts:336-337, 394-397`); every model edit is a scripted `nodeValue` write so the browser has no history to offer. The comment's claim that the browser stack is empty is wrong in one respect: composition commits are browser edits and do go on it; harmless only because the event is cancelled. Natives have only the platform's plain-text undo, which is not model-aware, so a model-level stack is also a port-back candidate.

Design notes for a model-level history:

- [ ] Hook `historyUndo`/`historyRedo` in `handleBeforeInput` (they already reach it) and expose `undo()`/`redo()` on the host and the ref API (natives would need the same methods for parity).
- [ ] Snapshot = `{ text, formattingRanges, blockRanges, selectionBefore, selectionAfter }` or inverse edits `{ editStart, deletedText, insertedText, rangeDiffs }`; `applyEdit` already receives exactly the forward edit (`InputHost.ts:738-761`), and `EditContext` carries `deletedText`, so inverse text edits are free; range/block diffs are easiest as snapshots of the two store arrays (they are small: ≈ 45 KB measured for the 522-range jsdom doc in the reference measurements, so roughly 4× that at 2072).
- [ ] Coalesce consecutive single-character inserts/deletes at an adjacent caret into one entry; break on: selection move not caused by the edit, a newline, a block/inline command, a pause (e.g. 500 ms), composition boundaries (one entry per committed composition), paste/cut.
- [ ] Imports: `setValue`/`defaultValue` should clear the stack (or push a boundary) — natives reset their UITextView/EditText history on `setText`.
- [ ] Restore `selectionAfter` on redo and `selectionBefore` on undo; route through `writeSelectionToDom` (respecting the composition guard above); emit text/selection/state/markdown like a normal edit.
- [ ] Typing attributes: an undo that removes a style range should reseed pending styles from the restored caret, not keep the pre-undo pending set.
- [ ] If the "browser owns plain typing" option from P1-A is taken, decide whether to keep the browser's native stack for plain typing or intercept `historyUndo` uniformly; mixing both is the classic source of desync (Lexical/ProseMirror both intercept uniformly).
- [ ] Tests: undo after each edit type (type, Backspace, Enter, Tab indent, toggles, paste, cut, composition), coalescing boundaries, undo across an import, redo invalidation on new edit, 2 instances with independent stacks.

### P1-C — Easy and important performance

Ordered by payoff ÷ effort. Items 1–4 are small, local changes.

- [ ] **1. No `render()`/`serialize` on no-op paths** (see P1-A): `setSelection`, selection-change fix-up, caret-only toggles, invalid heading level (`toggleHeading` with a bad level still renders and emits; iOS returns early at `I/EnrichedMarkdownTextInput.mm:998-1004`), empty `insertText`, `insertText('')` with a caret still fires three events. Skip `emitMarkdown` when the document is unchanged (or equals the last emitted string).
- [ ] **2. Quadratic import walk on list-heavy documents** (`W/formatting/InputParser.ts:159-160, 196`): `state.text.endsWith('\n')` flattens the growing cons string once per list item and is the whole quadratic cause (fact-check, isolated: 743 ms @ 10k, 12.2 s @ 40k); `indexOf('\n', itemStart)` at `:196` costs 0.3 ms @ 10k and is not a cause. `blankRuns.shift()` (`:188`) is O(n) but only runs for top-level blocks, so it matters for paragraph-heavy docs (40k paragraphs: 141 ms walk), not list-heavy ones. - [ ] **3. `completeMarkdown` is the largest import CPU phase**: 3.7–4.8 ms per 63 KB, about 2.4–3× the WASM parse, because it tests up to 8 delimiter pairs with `startsWith` per character (`W/formatting/InputRemend.ts:36-108`). Switch on `charCodeAt` and only handle `\ ] ) * _ ~ | \` [`; expected 5–10×.
- [ ] **4. Line scans in BlockStore are char-by-char loops** (`W/formatting/BlockStore.ts:27-34, 147-148, 169, 327-329`): on a 1 MB doc with 20k list lines `normalizeToLineBounds` costs 19 ms per keystroke and `pruneOrphanedAnchors` 20 ms per deletion [J]. Prune check = `anchor === 0 || text.charCodeAt(anchor-1) === 10` (0.16 ms vs ~15); `paragraphBounds` via `lastIndexOf`/`indexOf` (0.74 ms vs 15.2); only re-snap blocks on edited lines (everything else shifts by delta). `blockAt` also scans to the line end on every selection change (`InputState.ts:87`).
- [ ] **5. `replaceData` diff in `patchRun`** (P1-A).
- [ ] **6. `onChangeMarkdown` serializes the whole document per keystroke**: 0.86 ms here [B], 3.2 ms on 50 KB/2000 ranges/334 items and 5.8 ms on 130 KB in jsdom. Cache serialized output per line keyed by (line text, ranges touching it) and re-join, or coalesce emissions to one per frame. Also skip the `{...range}` copy for single-line ranges (`MarkdownSerializer.ts:102`), precompute newline offsets instead of `indexOf('\n', start)` per range (`:98`, ranges × line length worst case), insert block prefixes during the inline sweep to drop the two `split`s and the join (`:192-206, 258`), char-code whitespace test (`utils.ts:27-29`).
- [ ] **7. Incremental projection + renderer window hint.** `render()` re-projects the whole document (`InputHost.ts:769-775` → `W/render/InputProjection.ts:149-195`: `split('\n')`, per-line `computeStyleRuns` with a sort, fresh objects for all 583/1243 lines) and `changedWindow` re-diffs every line by content (`DomRenderer.ts:119-183`, ~2700 substring slices per keystroke). `applyEdit` already knows `editStart/deleted/inserted`: project only the lines spanning the edit, shift later paragraphs by delta, patch those lines directly. ≈ 60–70 % of the render's JS cost and most of the ≈ 217–269 KB garbage per keystroke [J]. Fall back to full projection when the edit contains `\n` or changes block metadata (ordinals renumber).
- [ ] **8. List insert rewrites every later item**: `sameParagraph` compares `ordinal`, and the store assigns ordinals to unordered items too, so Enter at item 0 of a 50-item bullet list produced 48 `characterData` mutations [B] (`DomRenderer.ts:164`, `BlockStore.ts:234`). - [ ] **9. Multi-line block commands are O(lines × blocks)**: each `setBlock` does a full `filter` + `splice`, called once per line; select-all `toggleListType` took 73 ms @ 2k lines, 605 ms @ 10k, 4.1–7.2 s @ 20k [J] (`BlockStore.ts:101-118, 243-253`). Binary-search the overlap window and splice in place (prototype: 7.2 s → 0.6 s), or one bulk merge pass. The "linear" claim at `:86-87` is wrong.
- [ ] **10. `rangeOfType` is a linear `find` from index 0** (`FormattingStore.ts:29-36`): 7 calls per keystroke, ~17 per caret move (`TypingAttributesController.ts:80-84`, `InputState.ts:30-77`). - [ ] **11. `allRanges` defensive copies** 4× per keystroke (`InputHost.ts:162-163, 767, 773-774`; `:162-163` only with markdown emit on; `:767` copies just to read `.length` but only on an empty document); return `readonly` views and add `isEmpty`. iOS mirrors the `.length` copy at `I/EnrichedMarkdownTextInput.mm:681`.
- [ ] **12. Import DOM build**: 1243 `insertBefore` calls into the live root (`DomRenderer.ts:104-109`); use a `DocumentFragment`. 13 ms in Chromium for 88 KB, 94 ms in jsdom.
- [ ] **13. Warm the WASM parser at module load / app start** (not at host construction: the wrapper constructs the host and starts the `defaultValue` import in the same layout effect, `EnrichedMarkdownTextInput.web.tsx:158-186`, so that gives no head start): after init the `cwrap` call is synchronous (`src/web/parseMarkdown.ts:44-68, 93-108`), so imports become effectively synchronous, which also removes the window where keystrokes are dropped during the first `defaultValue` parse (`InputHost.ts:340-342`; with `autoFocus` the user's first characters vanish).
- [ ] **14. `recomputeListMetadata` runs up to 3× per edit** (setBlock/removeBlock/prune each recompute, then normalize again). Recompute only in `setRanges` and normalize like the natives; this also deletes `batchWrites`/`deferredRecomputes` and fixes the nested-depth bug (§2.3).
- [ ] **15. WASM limits** [R]: `cwrap('string')` copies the input onto the 8 MB WASM stack (`packages/core/cpp/wasm/build.sh` `STACK_SIZE=8MB`), multi-MB documents approach an unchecked overflow; the JSON result lives in a static `std::string` until the next parse (`md4c_wasm.cpp:8,50`); memory never shrinks. JSON output is 2–6× the markdown size depending on formatting density (132 KB for 65 KB; 2.25× plain-ish, 5.9× format-dense).

## 2. Correctness findings by module (P2 unless noted)

### 2.1 InputHost.ts — DOM/event side

1. Composition read-back caret bug, composition guards, missing `input` listener, placeholder, composed text excluded from value, target ranges, word/line delete: see P1-A.
2. **Paste and cut rely only on ClipboardEvents** (`:112-113, 384-387`). With `dom.event.clipboardevents.enabled=false` (hardened Firefox/LibreWolf) paste does nothing and cut copies without deleting. Handle `insertFromPaste` from `event.dataTransfer` and `deleteByCut` via target range when the clipboard handler did not run.
3. **Clipboard parity** (`:474-508`): copy is not intercepted (browser writes html+text), cut writes `text/plain` only, paste inserts literal text. Natives write a markdown flavor on copy/cut and parse pasted text as markdown (`I/ENRMInputTextView.mm:18-66`, `A/EnrichedMarkdownTextInputView.kt:805-831`). Copy→paste inside the editor loses formatting; `- item` pastes literally [B].
4. **Ctrl/Cmd+B/I/U do nothing** (`formatBold` etc. cancelled, `:392-393`); no code handles these shortcuts. Map to `toggle*`. `insertTranspose`, `insertFromYank`, `deleteEntireSoftLine`, `insertFromDrop` also dropped silently.
5. **Tab/Shift+Tab always consumed while editable** (`:418-429`): keyboard trap (WCAG 2.1.2); Tab on a plain paragraph starts a bullet list [B]; iOS inserts `\t` outside lists (`I/EnrichedMarkdownTextInput.mm:1140-1151`), Android inserts `\t` for every unmodified Tab, inside lists too (`A/…View.kt:250-255`, before `handleListKey`); Shift/Ctrl+Tab still move focus. Tab also skips the `pendingImports` check every other edit path has. Handlers ignore `event.defaultPrevented` (an ancestor capture listener cannot veto).
6. **`role`/`aria-multiline` set via `setAttributeIfAbsent` are never added to `ownedAttributes`** so `destroy` leaves them (`:94-95` vs `:58-63`); after a StrictMode remount the second host treats them as the consumer's.
7. **No-op edits still render and emit** (empty `insertText`, `data: null`, collapsed target ranges) (`:738-761`).
8. **Public methods have no `destroyed` guard**: after `destroy()`, `setSelection`/`toggleBold`/`insertText` repopulate the consumer's node, fire callbacks and log "Patch failed; rebuilding the DOM" [J]. Wrapper is protected by `host.current = null`; direct users are not.
9. **`applyEdit` assigns `this.text` before the pipeline runs** (`:743-758`); a throwing pipeline leaves text updated, stores half-adjusted, DOM stale. No throwing path found today.
10. **`insertText('\n')`/pasting `\n` on an empty list item continues the list** instead of exiting; only the Enter key path exits (`:600-616`). Natives exit inside the pipeline for typed/IME newlines (`A/editing/EditPipeline.kt:144-153`; `I/ENRMEditPipeline.mm:203-221`; iOS keeps the newline, Android/web delete it), but their `insertText`/paste go through `pasteMarkdown` → `replaceTextInRange`, which bypasses that pipeline (iOS Formatting phase, `I/EnrichedMarkdownTextInput.mm:717-815`; Android Processing phase, `A/…View.kt:512-528, 856-880`), so natives neither continue nor exit there. Decide the intended behavior instead of "match native".
11. **`insertText`/`insertReplacementText`/U+2028/2029 are not line-ending normalized**; only paste is (`:940`). iOS also splits lines at `\r` and U+2029 (`I/ENRMBlockStore.mm:8-16`). `\r` through `insertText` re-imports as a line break.
12. **`setValue` in the same task as a keystroke**: `ImportQueue` defers the import by a microtask, so a synchronous keystroke right after `setValue` is applied (and emitted) then overwritten [B]. Harmless result, spurious `onChangeText`.
13. Stale comment at `:389-391` says Enter is "still deliberately denied"; it is handled at `:354-357`.

### 2.2 InputHost.ts — commands, import, API

1. **`insertText` does not follow the documented API** (`API_REFERENCE.md:1306`): natives parse the argument as markdown and treat `''` as a no-op (`I/EnrichedMarkdownTextInput.mm:1359-1365`, `A/…View.kt:962-965`); web inserts literally with pending styles; `insertText('')` with a range deletes the selection [J] (`:660-667`). 7. **Keystrokes dropped during the first parse** (P1-C #13).

Emit copies.

10. **Caret-only toggles re-render and re-serialize** (`:650-658`); Android emits only state (`A/…View.kt:621-633`).

### 2.3 Stores — BlockStore, FormattingStore, RangeEditAdjustment

1. **Nested-list depth lost on merge/delete** (`W/formatting/BlockStore.ts:150-154`, via `W/editing/EditPipeline.ts:55-57`): `pruneOrphanedAnchors` recomputes list metadata before `normalizeToLineBounds` stretched the merged-into block, the next item fails adjacency and its `level` is clamped in place. `- a / - b(1) / - c(1)`, Delete at end of "a" → `- ab / - c(0)` [J]. Natives recompute only in normalize. Fix: drop the recompute (verified: all 401 web-input tests still pass with it removed, and the example keeps `  - c`).
2. **Enter at the start of a non-empty list item splits the list** (`EditPipeline.ts:76-82`, `BlockStore.ts:260-265`): `1. a / 2. b`, Enter before "b" → `1. a\n\n1. b` (re-imports as one loose list); `- a / - b(1)` → b drops to depth 0 [J]. iOS inserts an empty item above (`I/ENRMEditPipeline.mm:221-222`); Android swallows the Enter (`A/editing/EditPipeline.kt:145-153`). Fix: when the closed line is empty and the next line is a list item, stamp its type/level on the closed line in the same batch.
3. **A selection ending exactly at a line start includes that line** (`BlockStore.ts:44-58`): Chrome triple-click on line 1 maps to `{0,4}` and `toggleHeading(1)` converts line 2 too → `# one\n# \ntwo` [B]; multi-line `toggleHeading(2)` over `a\n\nb\n\nc` turns blank lines into `## ` [B]. iOS stops at the last selected character's paragraph; Android has the same bug (`A/editing/BlockEditCoordinator.kt:182-195`). Fix: for a non-empty selection use `end-1` when `text[end-1] === '\n'` (Slate `unhangRange`).
4. **`setRanges` trusts parser output that breaks invariants** (`BlockStore.ts:71-76`; `FormattingStore.ts:17-19`): setext `Foo\nbar\n===` → one h1 [0,7] over two lines (toolbar shows no heading on "bar", first keystroke silently changes `# Foo\n# bar` → `# Foo\nbar`); `- # foo` → h1 and list item both at 0 (renders heading, serializes `- # foo` until a keystroke drops the marker); `**foo **bar** baz**` → strong 4–7 plus strong 0–11, and `removeType` assumes same-type ranges never overlap: `setSelection(5,6); toggleBold()` → `**foo **b****a****r** baz**` [B]. Normalize on import (split multi-line blocks per line, resolve same-start blocks, merge overlapping/touching same-type+url ranges). Same unnormalized `setRanges` on iOS (`I/ENRMFormattingStore.mm:33`) and Android (`A/formatting/FormattingStore.kt:12`).
5. **`adjustForEdit` can break the sorted-by-start invariant** `InputProjection.ts:163-176` relies on (`FormattingStore.ts:219-232` + `RangeEditAdjustment.ts:73-82`): a link and a style sharing a start (parser emits post-order, so `**[world](u) more**` has link first), then a replacement at that position keeps the style's start but moves the link's. E2E on `**[world](https://u) more** tail`: markdown `**X**\n**Y[rld](https://u) more** tail!` with line 1 rendered plain [J]. Precondition: no pending `strong` at the edit (a pending `addRange` re-sorts and hides it), so the realistic path is a spellcheck/autocorrect replacement away from the caret. Stable re-sort when both deleted and inserted lengths are > 0.
6. **Empty-line join result depends on whether the next line has a block** (`BlockStore.ts:301-311, 171-179`): empty H2 at 0 + Delete turns `bbbb` into H2, but if `bbbb` is a list item the item wins and the H2 disappears [J]; iOS keeps array order so the empty line's type wins in both. `BlockStore.test.ts:316-331` pins the flip using an explicit `'paragraph'` block the parser never produces.
7. **`addRange` merges touching links regardless of URL and takes the new URL** (`FormattingStore.ts:84-101`), contradicting the invariant at `:6-8`; `toggleStyle('link', …)` produces a url-less link. Unreachable today (links only via import, `setLink` stubbed) but both natives insert links through `addRange`: `setLink` on "b" in `[a](x)b` → `[ab](y)` (`I/ENRMLinkCoordinator.mm:46-49`, `A/editing/LinkCoordinator.kt:53-58`).
8. **Empty spans not guarded**: `removeType('strong',5,5)` on 0–10 splits into touching 0–5 and 5–10 → `**abcde****fghij**`; `addRange` with an empty range stores a zero-length range (`:104-137, 80-102`).
9. **`setBlock` doc says it covers every paragraph in the range; a multi-line range creates one block that normalize clips to the first line** (`BlockStore.ts:98-100`). Narrow the signature to a line start.
10. Heading `level` is stored twice (`type` and `level`); `createBlockRange('h2', …)` defaults level to 0, so the level-less heading fixtures in `BlockStore.test.ts` are "inactive" per `InputState.ts:88` (other suites pass explicit levels) (`W/model/blocks.ts:61-77`). iOS derives the level from the type.
11. Select-all + type over `para\n- item` makes the new text a list item; select-all + Backspace leaves an empty anchored block when the last line carries it (`# head` → `# `, `data-empty` false, placeholder hidden; `# head\nfoo` clears cleanly; `foo\n\n- item` gives empty markdown while the DOM keeps a list-item div) [B]; indent with a paragraph at the selection start converts ordered items to bullets; outdent from a depth-0 start un-lists nested lines too (`BlockEditCoordinator.ts:35-44`). All shared with natives (`collapsed` rule `BlockStore.ts:283-291`; `I/ENRMBlockStore.mm:163-171`; `A/formatting/BlockStore.kt:114-117`). Decide the rule once.
12. Only `\n` splits lines on web (iOS also `\r`, U+2029).

### 2.4 Typing attributes and state

1. **Caret toggle inside or at the start of a styled run needs two presses** (`W/editing/TypingAttributesController.ts:54-64` with `FormattingStore.ts:161`): the selection move pre-seeds pending `{strong}`; the first press only deletes that copy while the store still says active, so no `onChangeState` fires and typing X inside `ab**cd|ef**gh` gives `ab**cdXef**gh` [J]. iOS has the same bug (`I/ENRMInputTypingAttributesController.mm:61-78, 194-222`); Android flips add↔remove correctly (`A/…View.kt:621-632`). 2. **Range-selection state uses whole coverage; both natives use the first character** (`W/editing/InputState.ts:53-60, 72-75`): `[1,4)` over `**ab**cd` → web `bold:false`, natives `true`; link state for a range violates the documented contract (`src/types/MarkdownTextInputInstance.ts:9-16`): `isActive:false` with non-empty destination; `InputState.test.ts:43-45` claims "matching the natives" and is wrong, `:46, :157-172` pin the divergence. Typing over a selection disagrees with the state (select all of `**ab**cd`: state false, typing X gives `**X**` because pending styles seed from the first character).
3. **Newline positions are never "covered"** (`FormattingStore.ts:63-77, 149-151`): select-all over `**a**\n\n**b**` reports bold off; first Bold press adds a range spanning the newline with unchanged markdown (looks like a no-op); second press unbolds [J]. iOS shares the toggle code (`I/ENRMFormattingStore.mm:111-131`). 4. **Caret inheritance rule differs**: web/iOS seed from `isStyleAdjacentBefore`, which checks the position itself too (`FormattingStore.ts:52-60`), so typing before a bold run mid-line becomes bold (`a **Xbold**`), contradicting `RangeEditAdjustment.ts:106-110`; offset 0 never inherits but a line-2 start does; Backspace removing the last bold char keeps bold; Enter carries pending styles to the new line. 5. `isEffectiveStyleActive`'s `type !== 'link'` branch is unreachable (`TypingAttributesController.ts:29-42`); `TYPING_ATTRIBUTE_STYLES` hand-duplicates `INPUT_STYLE_TYPES`; `buildInputState` takes both the store and `typing` (which wraps it); `linkForSelection` should live with the store/link coordinator since `setLink`/`removeLink` must share the lookup; comment at `TypingAttributesController.ts:9-11` is wrong (pending styles persist across characters until the selection moves).

### 2.5 Parser, remend, WASM glue

1. **No flanking check in `completeMarkdown`** (`W/formatting/InputRemend.ts:75-85`): iOS/Android added `isEmphasisOpener` in #798 (`I/ENRMInputRemend.mm:52-60,124`, `A/formatting/InputRemend.kt:135-144,74`) before this port. Because web builds plain text from the *completed* source, unused closers become literal text: `snake_case` → `snake_case_`, `https://x.com/foo_bar` → `…foo_bar_`, `2 * 3` → `2 * 3*`, `* item` lists with odd item counts, `~~ approx` becomes a strikethrough; the editor's own output `snake_case is fine` re-imports as `…fine_` [B]. `InputRemend.test.ts:54-61` pins the no-flanking behavior as a "known limitation" (with `2 ** 2` and `a || b`). Port `isEmphasisOpener` (whitespace 0, `[\p{L}\p{N}]` 2, else 1) together with the native intraword-`_` rule (`_` with level 2 on both sides never opens); without it `snake_case` still opens.
2. **`***` is one token**: `**bold *nested***` → `bold nested******`, `*a **b***` → `a b******`, growing on every save/load [B] (`InputRemend.ts:8-9, 76-80`). The serializer emits exactly this shape for italic-contains-bold ending together. Android same (`bold nested***`); iOS protected by `isComplete`/`originalLength` (`I/ENRMInputParser.mm:376-377, 406, 519`). Fix: when `***` meets `*` and `**` as the top two stack entries, pop both.
3. **Completion closers are applied and leftovers leak** (Android behavior; iOS keeps input literal): `**force push` → bold; `a*b` → `ab` italic b; `see [1` → `see [1]`; `**draft\n\nnext para` → `**` appended to the next paragraph (stack carries across blocks); `` `*` `` → ``*``*``; a fenced block with `a_b` gains a stray `` ```_ `` line and degrades further on every reload. Remend knows nothing about code spans, fences or block boundaries. Options: skip completion on import (it only runs there), or adopt iOS's rule (drop spans/text from the suffix; needs byte→UTF-16 offset map like `I/ENRMInputParser.mm:119-150`).
4. **Admonitions glued to the previous block**: `INPUT_PARSE_FLAGS` (`InputParser.ts:33-41`) leaves `admonitions` on (default true, `parseMarkdown.ts:89`) and `TOP_LEVEL_BLOCK_TYPES` lacks `Admonition`, `BlankLine`, `Video` (Android has them, `android/src/main/java/com/swmansion/enriched/markdown/parser/MarkdownASTNode.kt:50-64`): `para\n\n> [!NOTE]\n> hi\n\nnext` → `parahi\n\nnext`.
5. **Entities and HTML blocks are deleted** by the shared C++ parser: `MD4CParser.cpp:430` ignores `MD_TEXT_ENTITY` (`Tom &amp; Jerry` → `Tom  Jerry` [B]); flags at `:820` don't disable HTML blocks and their content is swallowed (`<div>hello</div>\n\nafter` → `after` [B]). iOS uses `MD_FLAG_NOHTML` (`I/ENRMInputParser.mm:354`). Affects Android input and the web display component too.
6. **List items with more than one block are merged**: separators skipped whenever `listDepth > 0` (`InputParser.ts:182-189`): `- a\n\n  b` → `ab` [B]; `- a\n  > q` → `aq`. Android same (`A/formatting/InputParser.kt:105`).
7. **Blank lines replayed at the wrong boundaries** (`InputParser.ts:26, 107-109, 188`): regex runs consumed FIFO at every boundary, wrong when a boundary has no blank line or blank lines sit inside a block: `# Title\nbody\n\n\n\nmore` → `Title\n\n\n\nbody\n\nmore` [B]; `- a\n\n- b\n\n\n\nc` → `a\nb\n\nc`; CRLF `a\r\n\r\n\r\nb` → `a\n\nb`. Fix and simplification: `preserveBlankLines: true` — the WASM emits `BlankLine{count}` at the right AST positions (verified), separator = `\n` + count more; drop the regex, `trim` and `countNewlines`. Also fixes `# h\nb` → `# h\n\nb` (document gains a line on first reload; `markdownRoundTrip.test.ts:56` pins the same mechanism with `# h1\n## h2` as "normalization").
8. **Unsupported constructs are flattened, not kept literal** (iOS keeps them as text): tables → `ab12` (test comment at `markdownRoundTrip.test.ts:66-69` says content "survives as plain paragraphs"; the cells are concatenated) [B]; `- [ ] task` → `task` (task lists always on, `MD4CParser.cpp:822`) [B]; images → alt text; code spans lose backticks [B]; fences keep a trailing newline and add a blank line [B]; `---` leaves extra blank lines [B]. Minimum: separators between table cells/rows.
9. Smaller: leading/trailing newlines dropped (`hello\n` → `hello`); import does not normalize CRLF though paste does; a NUL truncates the rest (`md4c_wasm.cpp:47` C string; iOS `strlen` same); setext `a\nb\n===` becomes one two-line h1 serializing as `# a\n# b`; two blocks on one line (`- # h`); empty list items vanish (`- a\n-\n- c` → `a\nc`); `nodeTypeToBlockType`'s `ListItem` arm runs but its result is always filtered out by `LIST_ITEM_BLOCK_TYPES` (dead); `LatexMathDisplay` cannot occur with `latexMath:false`.
10. **Rebuilt `md4c.js` shipped video support to the web display component** (picked up #765; `VideoRenderer` now renders `<video>`), while docs still say video is unsupported on web (`docs/docs/introduction/supported-features.md:67`, `docs/docs/react-native/guides/web-support.md:374`) and the NOTE in `build.sh:14-23` is stale. The C++ glue change itself is correct (new flag appended last, cwrap arity matches, default true keeps the display path unchanged, `em++` right for libc++).
11. **UTF-8 vs UTF-16 is not a problem**: the walk rebuilds text from decoded `Text` content, so offsets are UTF-16 (`café **naïve** 日本語 *😀x*` verified). Parse runs only on import; nothing parses per keystroke.

### 2.6 Serializer

1. **No escaping of plain text** (`W/formatting/MarkdownSerializer.ts:158, 166`; natives same; `markdownRoundTrip.test.ts:79-102` pins it): `5 * 2 = 10` → `…10*`, `x = a_b` → `a_b_`, `array[0` → `array[0]`, `true || false` becomes a spoiler, `` use ` here `` loses the backtick, `&copy; 2024` → ` 2024`, `1984. A novel` becomes an ordered item, `a\n===` becomes a heading, heading `Use #` → `Use`, list item text `- x` → `- - x`, link text `a]b`/`a[b` breaks the link. Typed `- item typed as text` / `# not a heading` re-import as bullet, h1 [B]. (`a_b_c` round-trips unchanged: the two `_` cancel in remend and md4c does not open intraword `_`.) Escaped forms round-trip with the current parser and `completeMarkdown` skips escapes (`InputRemend.ts:39-42`). Add an escape pass: inline `` \ ` * [ ] < `` plus `_ ~ |` (or only where they could act as delimiters) and `&` before `#?\w+;`; block markers at line start; trailing `#` run in headings.
2. **Nested styles sharing one edge are ordered by fixed type priority, not containment** (`:66-83, 151`): `[click **here**](u)` → `[click **here](u)**` → `[click **here](u)****`; `[**click** here](u)` → `**[click** here](u)`; spoiler[0,3)+strong[0,1) on "a b" → `**||a** b||`. Fuzz: 214/214 cases of this class failed. Fix: carry the other end in the event; order openings by `b.end − a.end`, closings by `b.start − a.start`, priority only when both ends match (prototype: 0 failures).
3. **Crossing ranges are interleaved** (`:151-164`): bold "ab" + italic "bc" → `**a*b**c*` → re-imports as `a*bc*******`; link[0,2)+em[1,3) → `[a*b](u)c*`. All 25 crossing fuzz cases failed. Fix: stack-based writer (close down to the deepest ended range, reopen survivors after skipping whitespace, open new ranges longest first); prototype passes 4602/4602 except intra-word italic/bold crossings.
4. **Delimiters next to punctuation/mid-word/CJK are not recognized by the parser** so markers stay literal: `**foo.**bar`, `**Note:**text`, `a**"b"**c`, `a**😀**b`, `**「引用」**です`, `_un_believable`, `~~old~~new`, `我_喜欢_你`. The "font styles outermost" priority makes it worse: valid `[**link**](u)s` and `x||**a**||y` are rewritten as `**[link](u)**s` / `x**||a||**y` which do not parse. Put link/spoiler outermost for identical extents (no fuzz regressions); where a delimiter cannot work, drop the style rather than corrupt the text.
5. **Empty list item written as a bare blank line** (`:251-253`): `- a\n\n- b` → re-imports as `a\nb` (item and line lost; ordered lists give `1. a\n\n3. b`). Write `-`/`2.` with no trailing space except right after a non-empty paragraph line (setext risk). In the DOM the empty item shows a `2.` marker that the markdown cannot express [B].
6. URL starting with `<` written bare (`:49`) → `[x](<foo)` loses the link; `\r` in plain text passes through (`# a\rb` re-imports as h1 `a` + paragraph `b`); in URLs it is percent-encoded (`:47`). Perf items in P1-C #6.
7. `Math.min` at `:156` redundant; the line-count invariant check at `:192-199` can no longer trigger now URLs are percent-encoded (and its `console.error` is unconditional, like `measureElement.ts:60`, while the EditPipeline/SelectionMapper/DomRenderer diagnostics are `__DEV__`-gated); width fallback at `:262, :279` reachable only from tests; depth clamped twice.

### 2.7 Rendering and styles

1. Renderer line ownership, IME leftovers, list-insert rewrites, `replaceData`: see P1.
2. **Strikethrough on a link loses the line-through**: `.enrm-link { text-decoration: underline }` has equal specificity and comes later than `.enrm-strikethrough`; only underline+strikethrough has a combined rule (`W/render/inputStyles.ts:97-99`) [B via agent]. **Strikethrough text is colored `#9CA3AF`** (≈2.5:1 contrast); read-only renderer colors only the line, natives apply no color.

4. **Headings and bullets ignore the root's font size and line height**: fixed px copied from the read-only defaults (`inputStyles.ts:21, 78-80`); with root `lineHeight:40px; fontSize:20px` h1 stays 38px (shorter than body) and the bullet stays `top:10px`. Native derives heading line height as heading size + (base line height − base font size) (`I/ENRMInputFormatterStyle.mm:120-130`, PR #885) and bullets at 0.3× font size centered. Use `calc(1em + var(--enrm-extra-leading))`, bullet `top: calc(0.5lh − 0.15em)`, size `0.3em`.
5. **No `markdownStyle`, `selectionColor`, `cursorColor`, `writingDirection` on web**; one static stylesheet built from the *read-only* defaults (`DEFAULT_NORMALIZED_STYLE`), not the input defaults: grey list markers vs native text color, 26px default line height vs native natural, no dark-mode path (fixed body `#1F2937`, headings `#111827`). RTL: `padding-left`/`left` don't flip (`inputStyles.ts:44-46, 66`). React treats a numeric `lineHeight` as a unitless multiplier. Fix: CSS custom properties on the root (pattern already used for `--enrm-placeholder-color`), `::selection` reusing `ENRM_SELECTION_BG_VAR` from `globalStyles.ts:5`, `caret-color`, logical properties; `MarkdownTextInputStyle`/`normalizeMarkdownTextInputStyle` are currently unused on web.
6. **A consumer `className` cannot override base styles**: `.enrm-input` is injected at the end of `<head>` with single-class specificity; `.my-editor { font-size:20px }` loses [B via agent] (`inputStyles.ts:53-61`). Wrap in `:where()` or `@layer`. Stylesheet goes into the global `document`, not `root.ownerDocument`/shadow root.
7. `__DEV__` inside the renderer's recovery `catch` (`DomRenderer.ts:69`), on the keystroke hot path (`EditPipeline.ts:35`) and in `SelectionMapper.ts:26`: `ReferenceError` under Vite/Next without a define, on every keystroke via EditPipeline, not only in the rebuild. The read-only `EnrichedMarkdownText.tsx:86` has the same issue on `main`. Use `typeof __DEV__ !== 'undefined' && __DEV__`.
8. `data-url` is written but never read (`DomRenderer.ts:299`). XSS: safe today (text/URLs only reach `nodeValue`/`dataset`, classes from a fixed enum, `javascript:` URL stored as `data-url` only [B]); if links become `<a href>`, block `javascript:`.
9. Minor visuals: spoiler `border-radius` per span (notches when split by bold); `pre-wrap` vs `break-spaces` (caret stuck at trailing spaces on wrapped lines); no `tab-size`; bullet center 2px left of native. Web draws a marker on every empty list line; natives only on the caret's empty line.
10. Projection: a link partly overlapping bold, anchors on the last line after a trailing `\n`, run boundaries never splitting a surrogate pair, and the sorted-ranges precondition are untested.

### 2.8 React wrapper, types, packaging, docs
